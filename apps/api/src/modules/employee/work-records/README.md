# 企业微信考勤与汇报接入边界

考勤管理与工作汇报是两个独立业务模块，分别使用独立权限、页面和接口。工作日报的真实来源是企业微信智能表格；考勤页面读取 `employee_wecom_checkins` 中已同步的企业微信打卡数据，不在浏览器直接请求企业微信。工作汇报展示仍保持既有独立实现。

## 企业微信数据形式

- 日报：使用智能表格 `record_id` 作为外部唯一标识，保存填写人、部门、填写时间、汇报日期、今日总结、明日计划、其他事项和附件元数据；同时保留原始字段 JSON，防止智能表格新增字段时丢失数据。
- 打卡：按时间范围和企业微信成员 `userid` 获取打卡记录，原始数据包含上下班类型、打卡时间、异常类型、地点、排班时间等；接入层将其归一为员工、班次、上下班时间、状态和地点。
- 人员关联：使用企业微信 `userid` 作为外部人员标识，通过明确映射关联员工档案，不使用姓名作为唯一键。

## 正式接入所需配置

1. 企业 ID（CorpID）和具备汇报、打卡读取权限的应用凭证；凭证仅存放在服务器环境配置中。
2. 将服务器公网出口 IP 配置为企业可信 IP。备案域名用于网页授权或可信域名，不替代公网 IP。
3. 确认应用可见范围覆盖需要同步的成员，并记录企业微信汇报模板 ID。
4. 完成人员 `userid` 与员工档案映射。

后台定时任务通过游标分页扫描并按 `record_id` 和内容哈希幂等 upsert。页面只能读取平台内的标准化结果，不得在每次打开页面时串行请求企业微信全部明细。
