# 和工作维护说明

本目录保存当前有效的架构与维护文档。历史方案、一次性排查记录和敏感运行信息不应放入这里。

| 文档 | 用途 |
| --- | --- |
| [PROJECT_STRUCTURE.md](PROJECT_STRUCTURE.md) | 项目目录、模块边界和主要文件职责 |
| `../README.md` | 项目入口、本地启动与常用命令 |
| `../DEVELOPMENT_LOG.md` | 按时间追加的开发变更记录 |
| `../TODO.md` | 后续待办事项 |

## 维护原则

- 前端业务功能放在 `apps/web/src/modules/<主模块>/<功能>`，通过模块注册表接入导航与权限。
- 后端按领域放在 `apps/api/src/modules/<领域>`；路由入口只负责组合认证、输入校验与服务调用。
- 数据库结构只通过 `apps/api/migrations/` 的顺序迁移变更，禁止手工修改生产表结构。
- `deploy/` 是生产配置模板来源，服务器部署使用 Git 中的模板与环境变量，不把密码、密钥或证书提交到仓库。
- `data/`、`.env`、`.runtime/`、`dist/` 和 `node_modules/` 均为本地或运行产物，不作为源码维护对象。
