# 企业微信考勤与汇报接入边界

当前模块通过 `EmployeeWorkRecordsSource` 读取数据，生产环境尚未配置企业微信时使用 `MockEmployeeWorkRecordsSource`。正式联通时新增企业微信数据源实现并在服务启动处切换，前端接口和驾驶舱数据结构无需改变。

## 企业微信数据形式

- 汇报：先调用“批量获取汇报记录单号”，按时间、创建人、部门或模板分页获得 `journaluuid`；再调用“获取汇报记录详情”。详情中的表单控件随企业微信汇报模板变化，因此统一转换为 `fields: [{ label, value }]`，不得把“今日完成”等字段写死在接入层。
- 打卡：按时间范围和企业微信成员 `userid` 获取打卡记录，原始数据包含上下班类型、打卡时间、异常类型、地点、排班时间等；接入层将其归一为员工、班次、上下班时间、状态和地点。
- 人员关联：使用企业微信 `userid` 作为外部人员标识，通过明确映射关联员工档案，不使用姓名作为唯一键。

## 正式接入所需配置

1. 企业 ID（CorpID）和具备汇报、打卡读取权限的应用凭证；凭证仅存放在服务器环境配置中。
2. 将服务器公网出口 IP 配置为企业可信 IP。备案域名用于网页授权或可信域名，不替代公网 IP。
3. 确认应用可见范围覆盖需要同步的成员，并记录企业微信汇报模板 ID。
4. 完成人员 `userid` 与员工档案映射。

正式同步应由后台任务分页拉取并持久化，页面只读取平台内的标准化结果；不要在每次打开页面时串行请求企业微信全部明细。
